# 校内LAN 起動・運用手順

## 1. 初回だけ

このフォルダで次を実行します。

```bash
npm install
npm run preflight
```

Node.js 20 以上を使用します。`npm run preflight` は、Node.jsバージョン、主要画面・正式SVG素材、保存フォルダへの書込み、主要npmスクリプト、TCP 8080番の利用可否をまとめて確認する導入前セルフチェックです。エラーが出た場合は `npm start` より先にその項目を確認します。

## 2. 毎日の起動

```bash
npm start
```

既定では `8080` 番ポートで、校内LAN向けに `0.0.0.0` で待ち受けます。

担任PC自身では次を開きます。

- 担任ホーム: `http://localhost:8080/teacher.html`
- 今日の出席・健康: `http://localhost:8080/attendance.html`
- 心の天気・教室のようす: `http://localhost:8080/dashboard.html`
- 児童画面: `http://localhost:8080/`

児童タブレットでは、担任PCのIPv4アドレスを使います。

例: 担任PCが `192.168.1.50` の場合

- `http://192.168.1.50:8080/`

## 3. iPad / Android への入れ方

標準運用は「アプリを各端末へインストールしない」方式です。iPad / Android のSafari・Chrome等から校内LANの児童画面URLを開きます。更新は担任PC側のサーバーだけで済みます。

担任ホームの初期設定では次を選べます。

- `インストールしない（推奨）`: ブラウザで使用
- `ホーム画面に追加（PWA）`: 学校のMDM・端末管理で許可されている場合に使用
- `切断時に自動再接続`: WebSocket切断時に再接続
- `一時切断中も画面を継続`: 直前の設定を利用して表示を継続
- 利用時間帯: 児童画面を使う朝の時間帯を設定

WebページだけでiPadやAndroidのブラウザを指定時刻に強制起動することはできません。自動起動や一括ホーム画面配布が必要な学校では、学校管理のMDM、Web Clip、キオスク/シングルアプリ設定等と組み合わせる前提です。個人判断で端末管理設定を変更しないでください。

## 4. 端末と児童のひも付け

担任ホームで学年・組、出席番号、児童名、端末IDを登録します。児童画面では学年・組を表示しますが、児童名を児童同士へ表示する用途には使いません。

C4thから書き出したCSVは、担任画面の「C4th 名簿連携」から読み込めます。CSVはブラウザ内で列対応を確認して名簿欄へ反映する設計で、外部クラウドへ送信する処理は入れていません。

## 5. 主な通信

- `GET /api/health` : サーバー稼働確認
- `GET /api/time` : 教室共通時計の基準時刻
- `GET /api/classes/:classId/today` : 最新の朝設定を取得
- `POST /api/classes/:classId/config` : 学級設定を保存・配信
- `GET /api/classes/:classId/dashboard` : 接続・心の天気・進捗の担任表示
- `GET/POST /api/classes/:classId/attendance/...` : 出席・健康観察
- `GET /api/classes/:classId/analytics` : 心の天気の集計
- `GET/POST /api/classes/:classId/calendar/:month` : 授業日カレンダー
- `GET/POST /api/classes/:classId/terms/:year` : 学期設定
- `GET/POST /api/classes/:classId/event-notes...` : 学校行事・季節メモ
- `WS /ws?...` : 設定配信、ACK、児童状態、再接続

担任が「初期設定・項目をクラスに反映」を押すと、サーバー上の学級設定を更新し、接続中の同じ学級の児童端末へWebSocketで通知します。

## 6. 通信が切れた場合

児童画面は直前の学級設定をブラウザのLocalStorageにも保持します。一時的にサーバーへ接続できない場合でも直前の朝タスクを表示し、WebSocketは自動再接続します。

再接続後は最新設定を取り直し、端末ACKと接続状況を担任ホームの配信モニターで確認できます。

## 7. Windows Defender ファイアウォール

学校の管理方針に従い、必要な場合のみTCP 8080番への受信を「ドメイン／プライベート」ネットワークに限定して許可してください。管理者権限や校内情報担当者の承認が必要な環境では、個人判断で設定変更しないでください。

担任PCと児童端末が同じ校内ネットワークにいても、ネットワーク分離や端末間通信禁止の設定があると接続できない場合があります。その場合は校内情報担当者へ確認します。

## 8. データ保存

サーバーは現在、主に次の領域へ学級ごとの情報を保存します。

```text
server/data/classes/      学級設定・名簿・端末設定
server/data/history/      心の天気・朝の進捗履歴
server/data/attendance/   出席・健康観察・学校暦・確認履歴・行事メモ等
```

出席・健康観察・心の天気は同じ画面で参照する場面がありますが、データ上は別項目として扱います。出席や健康観察の保存操作で心の天気を上書きしない回帰テストを用意しています。

## 9. 学校導入前に必ず確認すること

- 学校・自治体の個人情報、保存期間、バックアップの規程
- 担任PCの保管場所とアカウント管理
- iPad / Android のMDM方針
- TCP 8080番と端末間通信の可否
- C4thから出力できるCSV形式と校内で認められた取扱い
- 心の天気を診断・評価・順位付けに利用しない運用

この文書は現在の実装に合わせた開発・検証用手順です。実際の学校導入時には、自治体・学校のセキュリティ方針を優先します。
